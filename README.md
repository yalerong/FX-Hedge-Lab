# FX Hedge Lab

企业外汇敞口与套保工作台。本地运行，Python 标准库实现，无数据库、无第三方依赖、
**没有下单通道**——它不连银行，也不发任何交易指令。

**在线演示（合成数据）**：<https://fx-demo.pages.dev/>

录敞口 → 汇总净头寸 → 出锁汇建议 → 记录执行 → 到期回测与归因。

## 这个工具的立场

**决策变量是套保比例，不是汇率方向。**

汇率预测在这里不回答"该不该锁"。它只被允许做一件事：在六道闸门全部通过之后，
把已经定好的目标套保比例**往下**打一个折扣。折扣的取值域是 `{1.00, 0.70, 0.50}`，
**没有任何大于 1 的分支**——预测对你不利时，一律足额锁。

六道闸门（详见「[外汇预测接入](#外汇预测接入prophet)」）：

| # | 闸门 | 不通过时 |
| --- | --- | --- |
| 1 | 回测区间覆盖率 | < 80% 降一档，< 40% 直接 reject |
| 2 | 样本量与显著性 | support 档要求 n ≥ 24 且单侧二项检验 p ≤ 0.10 |
| 3 | 趋势一致性（GMMA 六层 EMA + ATR 归一化） | 与强趋势 5/6 相反则降一档 |
| 4 | 信噪比 | 预测幅度 ≤ 模型自身 MAPE 时，即使方向有利也不给折扣 |
| 5 | 预测区间覆盖 | 信号的逐月预测覆盖不到该到期期间时，模型对这段时间说不上话，不给折扣 |
| 6 | 信号时效与实时重估 | 信号缺生成时间、超过 45 天，或实时即期已改变预测方向时，不给折扣 |

这个立场不是保守，是因为**我们真的去验证过预测有没有用，结论是没有**——见
「[研究线与负结果](#研究线与负结果)」。

## 你可以用它做什么

- 录入未来要收或要付的外币金额。
- 自动按月份和币种汇总净敞口。
- 根据企业类型和套保比例生成锁汇建议。
- 一键把建议填入锁汇单。
- 记录实际执行的锁汇交易。
- 查看中性、乐观、悲观、自定义汇率场景下的预计损益。
- 到期后录入实际汇率，回测锁汇交易贡献。
- 每天自动拉取一次汇率并缓存到本地。

## 第一次启动

需要 Python 3.10 或更高版本；核心网页工作台不需要安装第三方包。网页工作台是日常使用的
推荐入口，命令行和桌面 GUI 是独立的离线模拟器，适合批处理和开发验证。

先打开 PowerShell，然后进入项目目录：

```powershell
cd FX-Hedge-Lab
```

启动本地网页服务：

```powershell
python web_app.py
```

看到类似下面的提示后，说明服务已经启动：

```text
FX risk web app running at http://127.0.0.1:8765
```

然后用浏览器打开：

```text
http://127.0.0.1:8765
```

第一次打开不会自动塞入样例账本。页面会让你选择 `空白工作区` 或 `加载样例`；样例日期会
按当天自动生成，既保留未来待办，也保留一条已结算记录用于复盘。顶部会持续
显示当前数据模式，“数据管理”区会显示实际状态文件路径。在线演示使用只读合成数据，
不会保存你的录入。

如果端口被占用，可以换一个端口：

```powershell

```

然后打开：

```text
http://127.0.0.1:8877
```

服务默认只允许绑定本机回环地址。确实需要在可信局域网访问时，必须显式添加
`--allow-network`；当前版本没有身份认证，不能暴露到公网或不可信网络：

```powershell
python web_app.py --host 0.0.0.0 --allow-network
```

## 页面怎么分区

页面按每天真实任务排序，左侧常驻导航可以直接跳：

- **待处理**：`待锁汇`（有几条建议侧栏会标几）、`录入`；有 Excel 时优先批量导入。
- **风险概览**：`驾驶舱`（组合层面的四个数：业务敞口合计 / 已锁合计 / 剩余敞口 / 待锁建议，
  外加分币种明细）、`净敞口`、`损益场景`。
- **执行复盘**：`明细`、`到期与回测`、`方案存档`、`变更记录`。
- **数据与设置**：`数据管理`、`汇率与缓存`、`配置`；原始 JSON 配置收在高级设置里。

驾驶舱的合计口径要注意一条：**各币种折成人民币后取绝对值相加，不同币种之间不互相抵消**。
净收美元和净付欧元是两个独立的风险，凑在一起算净额会把风险做小。同一币种同一期间的
收付已经在净敞口里抵过了。

同时也给**净额口径**（假设各币种同向变动、允许天然对冲后的净额）。两个数答的是
不同问题：绝对值口径问「风险量级有多大」，净额口径问「真正还敞着多少」——
后者成立的前提恰恰是那个相关性为 1 的假设，所以只能并列，不能取代。

## 口径与设计决定

这一节回答的是「为什么这么算」，不是「怎么点」。想直接上手看下一节。

### 远期价从哪来

锁汇建议里的「交易汇率」是**远期价**，不是即期价。远期结汇从来不按即期成交——
中美利差 2~3%、半年期限，这一项就有 1% 以上的系统性偏差，比预测折扣闸门
（最多 0.5×）的影响还大。

取价顺序：

1. `forward_overrides` 里录入的**银行远期报价**——有真实报价就该用真实报价；
2. 按抛补利率平价从 `interest_rates` 的利差推：`F = S × (1 + i_CNY × t) / (1 + i_外币 × t)`，
   年化单利、`t` 是今天到该期间月末的年限（货币市场惯例）；
3. 缺利率或到期日已过 —— 退回即期价，并在卡片上标「即期兜底」说明原因。

配置里的默认利率只是让工具开箱能跑，**用之前请换成你自己的资金成本**。

一个直接后果：中性情景的合计损益**不再恒等于 0**。美元利率高于人民币，
出口商锁远期结汇要付贴水，这个成本以前被「远期＝即期」的假设藏起来了。

### 操作方向

锁汇的买卖方向**只由净敞口决定**：净收就卖出外币、净付就买入外币。
配置里的「企业类型」**不会覆盖它**——出口型企业也可能有一笔欧元应付，
那笔仍然要买欧元。企业类型现在只用来标出反常方向（出口型出现净付、
进口型出现净收），提示可能是录入有误，但方向照走净敞口。

### 覆盖与剩余风险

驾驶舱里「已锁」和「剩余敞口」不是简单的加减关系，有两个地方容易算错：

- **只有方向相反的持仓才算覆盖**，而且最多算到敞口本身那么多。收汇敞口配
  一笔买入外币不是套保，是加仓。
- **剩余风险取净敞口的绝对值**，不能写成「敞口 − 覆盖」。同向持仓
  （100 收 + 50 买入 = 净敞口 150）和超额套保（100 收 + 150 卖出 = 净空 50）
  两种情况下，剩余风险都比业务敞口**大**。

所以「已锁 + 剩余 = 业务敞口」这个等式**只在 0 ≤ 覆盖 ≤ 敞口 时成立**，
它不是不变量。多出来的那部分单列成「额外风险」，不会被抹掉——
为了守住一个漂亮的等式而把风险藏起来，是本项目踩过的真实错误。


### 两个绩效口径

回测同时给两个口径，因为它们能得出相反的结论：

- **交易员口径**：锁汇贡献 = 相对**到期即期汇率**多赚或少赚了多少。
- **司库口径**：结汇均价 vs **当月月均汇率**。企业财务按月均记账和考核，
  甲方真正会问的是这个。

司库口径再拆成两块：**套保效应**（锁汇把价格从到期即期挪到了结汇均价）
和**择时效应**（市场自己从月均走到到期即期，跟锁不锁没关系）。
把运气和决策分开，才知道该表扬谁。

月均汇率的来源按可信度排：`monthly_average_rates` 里财务录入的记账汇率 →
本地行情文件的当月平均（只有美元有）→ 都没有就显示「无月均基准」，不猜。

### 情景假设

默认所有币种同幅同向变动，**这等于假设币种之间相关性为 1**。对「净收美元 +
净付欧元」这类组合，两边会天然对冲、把合计风险算小——真实风险来自交叉汇率。
页面会把这个假设显式写出来。要按币种分别设，写在配置的 `scenario_shifts` 里。

### 方案快照

配置是可变的。改一次目标套保比例，历史建议全部跟着重算，于是回答不了
「**当初**是按什么参数给的这条建议」——回测、归因、复盘全都建立在一个
会变的地基上。

「待锁汇」区的**冻结为方案**会把当前建议连同当时的配置、汇率、预测信号
一起存成只读快照。之后改配置不会动它。

快照真正的用处不是存档，是反过来告诉你**参数已经漂了**。页面会把漂移
分成三类报：

- **影响建议金额的**（套保比例、企业类型、利率、远期报价……）——一旦变了，
  页面上的建议就和方案里的不是一回事了，标记为「已过期」；
- **只影响损益模拟的**（情景涨跌幅）——不算过期；
- **汇率变动**——只报不判，千分之一以内当噪声。

### 价差与量差

司库口径原来只答「结汇均价比月均好多少」，那是**纯价差**。但敞口本身也会
不准：订单黄了一半、客户改了金额。这部分差异跟汇率一点关系没有，混在一起
看就会把「订单缩水」记到套保决策头上。

在「添加到期实际汇率」里填上**实际发生额**（选填；订单彻底黄了就填 0），
回测就会做价量分解：

```text
量差 = (实际敞口 − 计划敞口) × 月均汇率        ← 跟汇率无关
价差 = 实际敞口 × (结汇均价 − 月均汇率)        ← 再拆成套保效应 + 择时效应
量差 + 价差 = 实际结果 − 计划结果
```

还会点名一个常见的真实损失来源：**敞口缩水但远期已经按计划金额锁了**——
敞口没发生，远期照样得交割，这部分是裸头寸。

### 风险类型的推荐

录入敞口时，系统按已有信息推荐一个风险类型并说明理由：

| 情况 | 推荐 | 理由 |
| --- | --- | --- |
| 已入账 / 已开票 | 资产负债表套保 | 已确认的外币资产负债 |
| 未入账、金额已定（概率 100%） | 合同/订单套保 | 已签约未入账 |
| 未入账、概率 < 100% | 现金流套保 | 高度可能的预期交易 |

**只推荐，不替你决定**：你没动过下拉框时它跟着推荐走，一旦你手动改过就
再也不改，只把分歧显示出来，会计科目按你选的走。

这条规则在后端 `web_app.suggest_category` 和前端 `web/app.js` 各写了一遍
（表单要实时提示，不适合每敲一下打一次接口），所以配了
`test_category_parity.py` 逐格对拍，和 `demo/parity_check.py` 同一个思路。

### 数据校验

- 风险类型只接受 `balance_sheet` / `cash_flow` / `order_contract` 三个值，
  表外值一律 400 拒收。历史数据里如果有表外值（例如 `export_order`），
  页面会标「未知类目」并说明会计科目按公允价值变动兜底——**不做猜测性映射**，
  猜错等于悄悄改掉会计科目。
- 概率必须落在 `(0, 1]`。
- 删除一条不存在的记录返回 404，不再是 200 + `deleted: 0`。

### 金额取整

金额走 `money.py` 的 Decimal 取整：**四舍五入**（`round-half-up`），不是 Python
内置 `round()` 的银行家舍入。范围有限——汇率、聚合中间量仍是浮点，
详见 `money.py` 顶部的说明。

### 改动留痕

每一次新增、修改、删除、改配置、导入、清空、恢复样例或恢复备份，都会往 `data/audit_log.jsonl` 追加一行，
记下时间、动作、对象、改之前和改之后。这个文件**只追加、不改写**——
状态文件 `data/fx_workspace.json` 是整份覆写的，改完就看不出改了什么、
改前是什么；审计日志用于回答“改了什么”，自动备份则用于真正恢复数据。
页面上的「变更记录」显示最近 30 条。

日志写失败不会影响主流程（宁可少一条日志，也不能让数据存不进去）。
这个文件不进仓库。

### 数据管理

第一次启动不会再直接写入演示样例；页面会让你选择 `空白工作区` 或 `加载样例`。
右上角会显示当前数据模式和 `data/fx_workspace.json` 的位置，避免把样例数据当成真实数据。

`数据管理` 区提供几类操作：

- `导出工作区 JSON` / `导入工作区 JSON`：整份工作区备份或迁移，导入前会自动备份当前状态。
- `导出明细 CSV` / `导入明细 CSV`：按敞口、锁汇、结算三类批量处理，导入会先全量校验，失败不会落盘。
- `导出明细 Excel` / `导入明细 Excel`：同样按三类明细处理 `.xlsx`，字段与 CSV 一致，不需要额外依赖。
- `撤销最近删除`：只恢复页面上最近一次删除的明细行。
- `清空业务数据`：只清空敞口、锁汇和结算记录，不等同于恢复演示样例。
- `恢复最近备份`：回到最近一次操作之前；恢复前也会再备份当前状态，因此可以恢复回来。

状态文件写入采用临时文件 + 原子替换。每次会改变工作区的操作都会保留滚动备份，
备份目录是 `data/backups/`，默认保留最近 20 份。启动时如果发现主状态文件损坏，
会先保留损坏文件，再尝试从最近备份恢复；没有备份时才创建空白工作区。

## 页面区域说明

### 1. 汇率与缓存

这里显示当前汇率来源、汇率状态和更新时间。

右上角有一个日常按钮：

- `刷新汇率`：立即从汇率接口重新拉取一次数据。

`恢复样例` 已移到“数据管理”，避免日常操作时误触。

如果某个敞口币种没有真实汇率，系统不会再用 `1.0` 兜底，也不会生成远期价、人民币风险或锁汇建议。
先刷新汇率，或在汇率缓存/配置里补齐该币种后再做决策。
刷新失败但仍有旧缓存时，建议只会标成试算且不能冻结为方案；只有内置兜底汇率时不生成建议。

默认汇率接口：

```text
https://open.er-api.com/v6/latest/USD
```

汇率会缓存到本地，默认 24 小时更新一次。

### 2. 添加敞口

敞口就是未来还没锁定汇率的外币收付款。

字段说明：

- `到期日`：预计收款或付款发生的日期。
- `币种`：例如 `USD`、`EUR`、`JPY`。
- `方向`：
  - `未来收外币`：例如出口收美元。
  - `未来付外币`：例如进口付欧元。
- `金额`：外币金额。
- `概率`：这笔业务发生的概率，默认 `1`，表示 100% 会发生。
- `风险类型`：
  - `资产负债表套保`
  - `现金流套保`
  - `合同/订单套保`
- `备注`：写给自己看的说明。

填完后点击：

```text
保存敞口
```

保存成功后，页面顶部会显示保存提示，并自动跳到“敞口明细”。

已有 Excel 台账时，优先在录入区选择明细类型并导入 `.xlsx`。导入会先全量校验，任何一行
不合法都会整批拒绝，不会留下半份数据。

### 3. 执行锁汇

这里用来记录你实际做过的锁汇交易。

字段说明：

- `交易日`：锁汇交易发生日期。
- `到期日`：锁汇交割日期。
- `币种`：锁汇币种。
- `操作`：
  - `卖出外币/远期结汇`：适合未来要收外币的情况。
  - `买入外币/远期购汇`：适合未来要付外币的情况。
- `锁汇金额`：锁定的外币金额。
- `锁定汇率`：实际成交汇率。
- `备注`：例如银行、交易编号、业务说明。

可以手动填写，也可以在“锁汇建议”里点击：

```text
按建议填入锁汇单
```

系统会自动把建议金额、方向、币种和汇率填进表单，你确认后再点击“记录锁汇”。

### 4. 锁汇建议

这里展示系统根据当前净敞口生成的建议。

你会看到：

- 推荐锁汇币种。
- 推荐锁汇金额。
- 操作方向。
- 当前参考汇率。
- 目标套保比例。
- 预计影响的损益科目。
- `查看汇率走势`：跳到 TradingView 公共行情页；这里只作参考，可执行价格仍以银行远期报价为准。

建议金额的基本思路是：

```text
建议锁汇金额 = 业务敞口 × 目标套保比例 × 预测折扣 - 已经锁掉的金额
```

目标套保比例来自配置（可以按月份与币种单独覆盖）。预测折扣只会调低比例、不会调高，
六道闸门任意一道触发就退回 1.0×，详见「外汇预测接入」一节。

如果已经锁掉的金额足够多，系统就不会继续建议重复锁汇。

配置里的 `风险阈值 CNY` **不参与这个计算**，它只用来在净敞口表里给偏大的行标一个
「超阈值」提示。

### 5. 净敞口

这里是汇总表。它把你录入的敞口和已经执行的锁汇交易放在一起看。

主要字段：

- `业务敞口`：业务本身带来的外币风险。
- `已锁敞口`：已经通过锁汇交易抵掉的部分。
- `剩余敞口`：还暴露在汇率波动里的部分。
- `当前汇率`：系统当前使用的参考汇率。
- `人民币风险`：剩余敞口按当前汇率折算的大致人民币金额。

### 6. 敞口明细

这里列出所有已经保存的敞口。

如果录错了，可以点击对应记录里的 `编辑`、`复制` 或 `删除`。删除后可以在 `数据管理` 里撤销最近一次删除。

### 7. 锁汇明细

这里列出所有已经记录的锁汇交易。

如果录错了，也可以点击 `编辑`、`复制` 或 `删除`。删除后可以在 `数据管理` 里撤销最近一次删除。

### 8. 预计损益场景

这里用来比较不同汇率场景下的预计损益。

当前支持四类场景：

- `中性`：使用当前汇率。
- `乐观`：按配置里的乐观涨跌幅调整汇率。
- `悲观`：按配置里的悲观涨跌幅调整汇率。
- `自定义`：按配置里的自定义涨跌幅调整汇率。

你会看到这些损益项：

- `未实现汇兑损益`
- `衍生品投资收益`
- `衍生品公允价值变动损益`
- `已实现汇兑损益`
- `合计预计损益`

每一行净敞口都会出现在这里，**不只是有新增建议的那些**。已经锁到目标比例、没有新建议时，
这一块显示的是剩余敞口本身的浮动损益（套保腿为 0），标题会写「当前敞口预计损益」。

### 9. 添加到期实际汇率

到期后，如果你知道真实汇率，可以在这里录入：

- `到期日`
- `币种`
- `实际汇率`
- `备注`

保存后，系统会在“回测结果”里计算锁汇贡献。

### 10. 回测结果

回测用来回答一个问题：

```text
这笔锁汇交易到期后，相比实际汇率，贡献了多少人民币损益？
```

它不是预测，而是到期后的复盘。

**没有录入到期实际汇率的期间**，系统会用当前市场价先试算一个数，并在卡片上标「试算」，
文字也会写明「尚未录入到期实际汇率」。看到这个标记就说明这一行还没结算，数字会随行情变动。

### 11. 配置

这里可以调整系统行为：

- `汇率接口`：默认使用 ExchangeRate-API 免费接口。
- `缓存小时`：默认 24 小时。
- `风险阈值 CNY`：仅用于在净敞口表里标出偏大的行，不参与建议金额计算。
- `企业类型`：
  - `综合型`
  - `出口型`
  - `进口型`
- `默认套保比例（%）`：例如页面填 `80`，表示建议锁 80%。
- `乐观场景涨跌幅（%）`：例如页面填 `3`，表示 +3%。
- `悲观场景涨跌幅（%）`：例如页面填 `-3`，表示 -3%。
- `自定义场景涨跌幅（%）`：例如页面填 `1`，表示 +1%。
- `支持币种 JSON`：例如 `["USD","EUR","JPY"]`，只允许三位大写币种，且不需要写 `CNY`。
- `资金利率 JSON`：例如 `{"CNY":0.019,"USD":0.043}`，用于没有银行报价时按 CIP 估算远期价。
- `银行远期报价 JSON`：例如 `{"2027-03:USD":7.08}`，有银行报价时优先使用。
- `分月分币种套保比例 JSON`：例如 `{"2027-03":{"USD":0.75}}`，覆盖默认套保比例；这里仍写内部小数。
- `分币种场景 JSON`：例如 `{"EUR":{"optimistic":-0.01}}`，覆盖全局乐观/悲观/自定义涨跌幅；这里仍写内部小数。
- `财务月均汇率 JSON`：例如 `{"2027-03:USD":7.12}`，用于回测里的财务记账口径。

没有确认过实时汇率、银行远期报价、资金利率、分月套保比例或场景假设时，页面会把锁汇建议标成“试算建议”，并列出待确认原因。

改完后点击：

```text
保存配置
```

## 外汇预测接入（Prophet）

`forecast/` 目录提供一个独立的预测管线：拉历史汇率 → Prophet 训练 → 月度滚动回测 → 输出信号文件。Web 端读取信号后，会按"预测方向 + 模型质量"两个门槛调整锁汇建议。

### 一次跑通

先安装依赖（首次安装 prophet 在 Windows 上可能需要 2-5 分钟）：

```powershell
pip install prophet pandas
```

然后从项目根目录运行：

```powershell
python -m forecast.pipeline
```

管线会自动扫描 `data/fx_workspace.json` 里录入的币种，给每个币种对 CNY 跑一遍：

1. 从 `exchangerate.host` 拉近 6 年历史日汇率，取每月最后一日，存到 `data/rates_history/{PAIR}.csv`（日线同时存 `{PAIR}_daily.csv` 供趋势 gate 用）
2. 月度滚动回测算 MAPE、方向准确率、80% 预测区间覆盖率，存到 `data/backtest/{PAIR}.json`
3. 输出未来 6 个月预测，存到 `data/forecasts/{PAIR}.csv`
4. 用日线算 GMMA 势能趋势 gate（方向 + 层级一致度 0~6）
5. 汇总成 `data/forecast_signals.json`

如果 exchangerate.host 要求 API key，可以：

```powershell
$env:EXCHANGERATE_HOST_KEY = "你的key"
python -m forecast.pipeline
```

或在命令行直接传：`python -m forecast.pipeline --access-key 你的key`

也可以指定特定币种：

```powershell
python -m forecast.pipeline --pair USD --pair EUR
```

历史已经拉过，只想重新训练：

```powershell
python -m forecast.pipeline --skip-fetch
```

### 信号怎么影响锁汇建议

每条信号有三个关键字段：

- `direction`：未来 6 个月相对当前汇率的整体方向（up / down / flat）
- `forecast[].lower / upper`：每月预测的 80% 区间上下界
- `mape`：滚动回测的平均绝对百分比误差
- `direction_accuracy`：滚动回测的方向准确率
- `interval_coverage`：实际值落在 80% 预测区间内的比例（应接近 80%，太低说明模型低估不确定性）
- `trend`：GMMA 势能趋势 gate（`direction` 方向、`alignment` 六层一致度、`energy` 带符号势能）
- `tier`：综合质量分档，`tier_reasons` 记录每一次降档原因
  - `support`：MAPE ≤ 2.5% 且方向准确 ≥ 55%，且同时满足——
    回测样本 ≥ 24、方向准确率通过单侧二项检验（p ≤ 0.10）、区间覆盖率 ≥ 70%
  - `caution`：MAPE ≤ 5% 且方向准确 ≥ 50%，且区间覆盖率 ≥ 40%；或 support 条件未全部满足降档而来
  - `reject`：其他（覆盖率 < 40% 视为预测区间失真，直接 reject）
  - 预测方向与 GMMA 强趋势（一致度 ≥ 5/6）相反时，再降一档

锁汇建议按下表给目标套保比例叠加一个倍率：

| tier | 方向不利 | 方向有利 |
| --- | --- | --- |
| support | 1.0× | 0.5× |
| caution | 1.0× | 0.7× |
| reject | 1.0× | 1.0× |

另有一道信噪比闸门：预测期末变动幅度若未超过模型自身 MAPE，说明"有利方向"仍在误差范围内，即使 support/caution 也不打折、按目标比例足额锁汇。

"方向不利"指的是：

- 未来要收外币（结汇）且预测外币贬值（down）
- 未来要付外币（购汇）且预测外币升值（up）

模型质量不达标（reject）时，系统忽略预测方向，落回原目标比例。

### 看不到 forecast 信息怎么办？

Web 端会自动检测 `data/forecast_signals.json`。这个文件不存在或为空时，建议卡片就只显示原有字段，不会报错。

## 研究线与负结果

除了工作台本身，这个仓库还有一条独立的研究线：**用新闻事件预测 USD/CNY 日内方向**。

**两轮样本外，两次负结果，全部登记在仓库里。**

| 轮次 | 样本外 n | 命中率 | p 值 | 安慰剂 | 增量检验 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| v1 新闻事件方向 | 207 | 53.14% | 0.2022 | 19.9% | p=0.50 | 五条验收过两条 |
| v1 波动目标 | — | 比值 0.929 | 0.478 | — | — | 三条全不过 |
| v2 境内变量 + 新闻筛选 | 110 | 54.55% | 0.1955 | 18.2% | p=0.5094 | 不通过 |
| v2 基线（去掉新闻） | 110 | 54.70% | — | — | — | 比加新闻还高 |

结论写进仓库：新闻相对于已经能看到的市场变量**没有可验证的增量信息**。
未过验收的信号**不接入**上面那个折扣器——原计划的接入 PR 直接取消。

三条约束是这条线的核心，也是这个项目最值得看的部分：

1. **规则 commit 必须早于结果 commit。** git 时间戳是"没有先看行情再挑新闻"的唯一凭证。
   审计链：规则 `5b4ef4b` / `e3fe981` / `a1c4da2` → 代码 `046b168` → 结果 `2b3e65a`。
2. **样本外只跑一次，跑完即定论。** 2025-01 ~ 2026-08 这段窗口已经用了两次，就此封存。
3. **意外与响应必须分段测量。** 这条硬约束单独挡掉了一个漂亮的假发现：
   `r0`（事件当日收益）样本外命中 **61.24%**、严格档 **78.57%**、p = 0.0001——
   但它与规则的输入变量处于同一时段，"用当天的市场反应预测当天的市场反应"
   是同义反复，**不可交易**。

v2 里还有一个"字面通过但被否决"的例子：`rF` 三条预注册条件全过（n=382、p=0.0033、
训练 55.69% → 样本外 57.07% 不衰减），仍被判假通过——零假设选错（该比的是
"永远看多"而不是 50%）+ 中间价是参考价不可成交。

完整记录：[`docs/event-driven-plan.md`](docs/event-driven-plan.md)（预注册规则）、
[`docs/event-driven-results.md`](docs/event-driven-results.md)、
[`docs/event-driven-plan-v2.md`](docs/event-driven-plan-v2.md)、
[`docs/event-driven-results-v2.md`](docs/event-driven-results-v2.md)。

## 在线演示怎么来的

<https://fx-demo.pages.dev/> 上跑的**就是这套前端代码**，不是另写的一份宣传页——
另写一份的话两边一定会漂。

工作台本身是 Python 服务，静态托管跑不了，所以 `demo/build_static.py` 做三件事：

1. 用一份合成的演示数据在本地跑一遍 `build_dashboard`，把结果烘成 JSON；
2. 原样复制 `web/index.html` / `app.js` / `styles.css`；
3. 在 app.js 之前插一段垫片接管 `fetch("/api/…")`——读接口返回烘好的数据，
   写接口一律 403 并给出可读提示；
4. 写一份 `_headers`，让 Cloudflare Pages 给每个响应加上安全头。

演示数据是刻意排过的，每种值得看的情形都留了一个：未来期间（远期贴水看得见、
中性情景不为 0）、录了实际发生额的已结算期间（价量分解 + 超额套保警告）、
只锁一半的敞口、没有本地行情序列的币种（诚实显示「无月均基准」）、
冻过的方案加一次参数漂移。

`test_static_build.py` 钉住这些：垫片确实注入了、且排在 app.js 之前。
这个脚本靠字符串锚点改 HTML，锚点一变垫片就**静默**不注入——
本地构建照样成功，部署上去才发现页面在打真实的 `/api` 然后白屏。

`_headers` 里真正在挡事的是三条：`frame-ancestors 'none'` 不让别人把演示站嵌进
自己的页面里做点击劫持，`connect-src 'self'` 让页面即便被注入也发不出外部请求，
`X-Robots-Tag: noindex` 给 `robots.txt` 补一道（robots.txt 只管爬虫抓不抓，
这个头把 noindex 标到每个响应上，非 HTML 资源也覆盖得到）。
`script-src`/`style-src` 保留 `'unsafe-inline'`——垫片是内联脚本、方法页是内联样式，
改成 hash 的话锚点一漂就是整页白屏，代价大于收益。

因为 CSP 只放行同源，页面**不能引外部资源**（CDN 字体、统计脚本都不行）：
本地 `python web_app.py` 不发这些头，这类回归在本地是看不出来的，
所以 `test_csp_stays_compatible_with_what_the_page_actually_loads` 在构建产物上
扫一遍外部来源，引了就红。

重新部署：

```powershell
python demo/build_static.py .\demo\_static
npx wrangler pages deploy .\demo\_static --project-name fx-demo --branch main
```


## 工程约束

几条被 CI 真正守住的约束，不是写在注释里的口号：

- **核心逻辑零第三方依赖。** CI 的「零依赖核心」作业会先断言环境里没装任何
  第三方包，再跑全套测试——装了依赖就看不出这个约束还成不成立了。
  只有趋势闸门需要 pandas，那组测试会自动跳过，另一条「完整套件」作业装上再跑一遍。
- **同一份逻辑写两遍的地方，必须配对拍闸门。** 目前有三处：
  demo 页与实现的折扣闸门（`demo/parity_check.py`，96 组组合）、
  `web_app` 与 `fx_risk_simulator` 的敞口聚合（`test_engine_parity.py`）、
  风险类型推荐规则的前后端两版（`test_category_parity.py`）。
  做法都一样：从对方文件里按标记抽出函数丢进 Node 跑，逐格比对。
- **接口层也要测。** `test_http_api.py` 起真的服务发真的请求：路由、参数校验、
  错误码、配置合并、审计落盘、并发写。这组测试第一次跑就抓到一个真 bug——
  `ThreadingHTTPServer` 默认 `request_queue_size=5`，十来个并发连接会被内核
  直接重置（客户端看到的是 `ConnectionResetError` 而不是超时，很难猜）。
- **金额取整是确定性的。** 见「[金额取整](#金额取整)」。

### 测试命令

```powershell
# 全部测试（含 HTTP 层、两套实现对拍、金额取整）
python -m unittest discover -p "test_*.py"

# demo 页与实现的闸门逻辑对拍
python demo/parity_check.py

# 模拟「没装第三方包」再跑一遍（CI 的零依赖作业跑的就是这个）
python run_zero_dep_tests.py

python -m py_compile fx_risk_simulator.py fx_risk_gui.py web_app.py
node --check web\app.js
```

push 和 PR 会由 GitHub Actions（`.github/workflows/tests.yml`）自动跑这几条。**本机装着 pandas，直接 `unittest discover` 测不出零依赖那条路径**——跳过用的装饰器写错了本地也全绿，只有 CI 会红，所以本地也留了一份模拟。

### 两套实现的关系

仓库里有两条独立的敞口计算路径，**这是有意的**：

- `web_app.py`：网页工作台，状态在 `data/fx_workspace.json`，独有预测折扣闸门；
- `fx_risk_simulator.py`：离线 CLI，输入是 case JSON，独有远期价、坏账率、
  情景对账校验（`validate_case`）。

两边各写了一遍"按方向定符号 → 按期间和币种汇总"。谁改了一边忘了另一边，
数字就会悄悄分叉，所以配了 `test_engine_parity.py`：同一份敞口喂给两条路径，
钉住聚合结果必须一致。和 `demo/parity_check.py` 是同一个思路——
允许存在两份实现，但必须配一道闸门。

## 常见问题

### 点击保存没反应怎么办？

先看页面顶部状态条。常见原因：

- 必填项没有填。
- 金额或汇率不是正数。
- 本地服务没有启动。
- 浏览器还缓存着旧脚本。

可以按 `Ctrl + F5` 强制刷新页面。

### 汇率刷新失败怎么办？

系统会继续显示本地缓存，但建议会标成试算，且不能冻结为方案。如果本地没有缓存，页面只用
内置兜底汇率维持展示，不会生成锁汇建议。先恢复真实行情或录入银行报价后再做决策。

### 为什么没有数据库？

当前版本是本地单机工作台，使用 JSON 文件保存数据，方便演示和快速试算。

正式多人使用时，建议改成：

- SQLite：轻量本地版。
- PostgreSQL：多用户 Web 版。

### 能不能不用网页？

可以。项目还保留了命令行和桌面 GUI，但它们读取独立的 case JSON，功能和网页工作区并不完全相同。
日常录入、建议、方案、审计、备份与恢复请优先使用网页工作台。

命令行输出 JSON：

```powershell
python fx_risk_simulator.py sample_data.json --pretty
```

命令行输出解释：

```powershell
python fx_risk_simulator.py sample_data.json --explain
```

桌面 GUI：

